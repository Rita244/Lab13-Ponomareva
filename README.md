## Контрольные вопросы

1. Программа аварийно завершается (вылетает)
2. C# проверяет их сверху вниз. Если общий Exception будет первым, он перехватит всё, и до конкретных ошибок код не дойдет
3. Всегда. И при успехе, и при ошибке, и даже если сработал return
4. TryParse быстрее и проще (возвращает true/false без вызова ошибки). try-catch тратит ресурсы на создание исключения
 • Когда что: TryParse — для проверки ввода пользователя, try-catch — для непредвиденных сбоев (файлы, сеть)
5. : Exception делает вfш класс "ошибкой" (наследником системного)
: base(message) передает текст ошибки в системный класс, чтобы его можно было прочитать в catch
6. Не хватает памяти. Ошибка переполнения стека настолько критична, что у программы просто нет ресурсов, чтобы запустить механизм try-catch
